# 뉴스 도메인 탐색 및 크롤링 검사

Python 3.10 이상만 필요하며 추가 설치 패키지는 없습니다.

CMD에서 이 폴더로 이동한 뒤 `start.cmd`를 실행하고 메뉴 번호를 선택하세요.
`start.cmd example.com` 또는 `python check.py https://example.com/news/123`으로도 실행할 수 있습니다.
`clear` 또는 `cls`를 입력하면 화면을 지우고, `b`는 메뉴로 돌아가며 `q`는 종료합니다. 메인 메뉴에서는 `0`으로도 종료할 수 있습니다.

## 메뉴와 실행 흐름

1. **뉴스 도메인 추가 탐색 및 저장**: 구글 뉴스 RSS에서 검색어에 해당하는 언론사 이름과 원본 사이트 주소를 가져옵니다. 기존 국내·해외 67개 후보 목록을 불러올 수도 있습니다. 같은 도메인은 중복 저장하지 않으며 기존에 지정한 뉴스 페이지 경로를 보존합니다.
2. **저장된 링크 검사**: Enter로 전체, `new`로 미검사·사용자 제공 결과, `1,3,6`처럼 번호로 선택 검사합니다. 각 사이트의 로그를 출력하고 완료되는 대로 결과를 저장합니다. 마지막에 가능 / 불가능 / 미검사로 묶어 표시합니다. Ctrl+C로 중단해도 완료된 결과는 남습니다.
3. **직접 추가 / URL 변경**: 도메인/URL과 언론사 이름을 입력해 저장합니다. 같은 도메인이 있으면 검사 URL을 바꿀 수 있습니다. URL을 바꾸면 이전 결과를 미검사로 초기화합니다.
4. **결과 보기**: 재검사 없이 저장된 결과와 사유를 표시합니다.
5. **검사 로그 보기**: 사이트 번호를 선택해 마지막 검사 로그를 봅니다.
6. **크롤링 가능한 도메인 내보내기**: 저장된 판정이 가능한 사이트만 중복 없이 TXT로 저장합니다. `crawlable_domains.txt`에는 도메인만, `crawlable_urls.txt`에는 실제 검사에 사용한 전체 URL을 한 줄에 하나씩 담습니다. 기존 파일은 최신 목록으로 갱신하며 가능한 사이트가 없으면 빈 파일로 저장합니다. 사용자 제공 결과도 포함하고 해당 개수를 화면에 안내합니다. 최신 상태가 필요하면 메뉴 2로 재검사 후 내보내세요.

권장 흐름: `start.cmd` → 메뉴 1에서 검색 또는 기존 후보 불러오기 → 메뉴 2에서 검사 → 분류된 결과 확인.

처음 실행할 때 사용자가 제공한 채널 A·JTBC·TBC·YTN·KBS·MBC의 링크와 결과 6개가 들어 있습니다. **사용자 제공·재검사 전**으로 표시되며 메뉴 2에서 검사하면 실제 앱 검사 결과로 갱신됩니다.

## 저장과 탐색 범위

- `news_store.json`: 이름, URL, 출처, 판정, 사유, 검사 시각, 마지막 로그를 저장합니다. 다음 실행 때 자동으로 불러옵니다.
- `results.txt`: 가능 / 불가능 / 미검사 목록과 판정 사유를 담은 읽기용 결과입니다.
- 저장 위치는 CMD의 현재 위치와 관계없이 앱 폴더입니다. 저장 파일이 손상되면 기존 파일을 덮어쓰지 않고 오류를 표시합니다.
- 구글 뉴스 RSS의 `<source url>`을 사용하며 구글 중계 기사 URL은 저장하지 않습니다. 네이버 자동 탐색은 제공하지 않으며 기존 후보 불러오기 또는 직접 추가로 등록합니다.
- 검색어별 RSS에 나온 출처만 가져오며 전체 입점 목록이 아닙니다. 기업 블로그 등 뉴스 전문 언론사가 아닌 출처도 포함될 수 있습니다. RSS 장애나 구조 변경 시 오류를 표시하고 기존 링크는 유지합니다.

## 검사 기준

- 도메인만 입력하면 HTTPS의 홈페이지를 검사합니다. HTTP 전용 사이트는 `http://`를 직접 붙이세요.
- robots.txt에서 CrawlCheck 전용 규칙 또는 일반 크롤러(*) 규칙을 확인하고, 허용된 URL에 GET 요청을 보냅니다. 페이지 이동 시 이동 대상 규칙도 먼저 검사합니다.
- HTTP 성공, 텍스트 형식, 80자 이상의 텍스트 수신을 모두 충족하면 `가능하다`를 출력합니다.
- 차단 규칙, 로그인 요구 HTTP 상태, 봇 검증 화면, 연결 실패, 규칙 조회 실패, 텍스트 부족은 `불가능하다`로 표시하며 로그에 원인을 남깁니다.
- robots.txt의 404/410은 규칙 없음으로 처리합니다. 다른 조회 오류는 보수적으로 불가능 처리합니다.
- 요청당 타임아웃은 10초이며 응답은 최대 1MB, 각 리디렉션은 최대 5회까지만 확인합니다. 인증서 검증을 유지하며 차단 우회는 하지 않습니다.

**이 결과는 입력 URL의 현재 HTTP 텍스트 접근 가능성을 나타내는 간이 검사입니다.** 홈페이지 성공이 모든 기사, 기사 본문 추출 또는 수집·재사용 허가를 의미하지는 않습니다. 로그인 화면이 HTTP 200으로 반환되거나 봇 검증 문구가 다르면 감지하지 못할 수 있습니다. JavaScript로 본문이 생성되는 페이지는 불가능으로 나올 수 있습니다. 실제 기사 URL을 입력하면 해당 경로의 규칙과 응답을 검사할 수 있습니다.

규칙 참고: https://www.rfc-editor.org/rfc/rfc9309.html

검증: `python -m unittest -v`
